# AGENTS.md — ord-dashboard

Локальная памятка по этому плагину. Общие правила — в корневом [`../AGENTS.md`](../AGENTS.md) и `../docs/`:
при конфликте приоритет у корневых документов. Идея и почерк продукта — `../docs/IDENTITY.md`.

## Состояние

Плагин переписан с нуля по стандарту репозитория (версия `0.1.0`): TypeScript в `src/`, сборка esbuild,
строгая типизация, линтер `eslint-plugin-obsidianmd`, данные — `saveData`, интерфейс — `ItemView`
в боковой панели. История прежней реализации и полный список исправленных дефектов — `../docs/PLUGINS.md`.

## Что важно знать при правках

- **Данные.** Всё лежит в `data.json` одним объектом: `{ version, settings, notes }`. Запись идёт только
  через `src/storage.ts` (`DashboardStore`). Не вызывайте `plugin.saveData(this.plugin.settings)` напрямую —
  это затрёт накопленную активность. Именно поэтому вкладка настроек переопределяет `getControlValue`
  и `setControlValue`.
- **Агрегаты, а не истории.** В `NoteActivity` нет массивов отметок времени: только счётчики, последние
  метки и месячные корзины (текущий месяц + два предыдущих). Если нужна новая метрика — добавляйте агрегат
  и подумайте, как её считать без полной истории.
- **Adapter API** используется ровно в одном месте — одноразовая миграция `note-views.json` из папки
  плагина (скрытые папки недоступны через Vault API). Новый код на adapter писать не нужно.
- **События** регистрируются только в `onLayoutReady` (иначе старт плагина обработает `create` для всего
  хранилища) и только для Markdown-файлов вне скрытых папок.
- **Граф связей** (`src/graph-*.ts`) — отдельный слой, повторяющий штатный граф:
  `graph-params.ts` (параметры сил/размера + чтение `graph.json` хранилища), `graph-model.ts` (чанковый
  сэмплер по `resolvedLinks`, оценка близости блужданием, различение связей и оглавлений, учёт места),
  `graph-layout.ts` (порт симуляции d3-force из воркера ядра), `graph-render.ts` (формулы отрисовки ядра
  на canvas 2D), `graph-view.ts` (блок с шапкой, взаимодействием и жизненным циклом).
  Правила: не выдумывать параметры и формулы — они взяты из ядра (`app.js`, `sim.js`) и из
  `.obsidian/graph.json`; менять движок только вместе с тестами в `docs/PLUGINS.md` (равновесие сил,
  сходимость 300 тиков, детерминизм, формулы размера/подписей); не копировать `resolvedLinks` целиком,
  не сканировать хранилище синхронно, не держать состояние при свёрнутом графе.
  Настройки применяются через `store.applySetting` (валидация в модели), а не прямой записью в объект.
  Типы узлов (теги, вложения, неразрешённые ссылки, сироты) и цвета берутся у ядра: данные — из
  `MetadataCache` только для выбранных заметок, цвета — теми же CSS-классами `.graph-view.color-*`,
  с перерисовкой по `css-change`. Не добавляй свои цвета и шрифты: в canvas нельзя использовать
  CSS-переменные, поэтому шрифт подписей берётся из `SIM_CONSTANTS.labelFont` (шрифт ядра).
  Отбор заметок в локальном режиме — единственное осознанное отклонение от ядра: «близость» считается
  блужданием (см. `docs/PLUGINS.md`, шестой и седьмой заходы), потому что в хранилищах с автоиндексатором два
  шага по ссылкам означают всё хранилище. Никаких имён папок, тегов и заметок в правилах отбора быть не
  должно: только структура связей, место заметки и доли от размера хранилища.
- **Имя плагина — всегда `ORD` заглавными и слово после него с маленькой буквы:** `ORDdashboard` в
  `manifest.name`, в заголовке `README.md`, в комментарии `styles.css` и в префиксах сообщений и `console.*`.
  Никогда `OrdDashboard`, `ORDDashboard` или `ORD Dashboard`. `id`, папка, репозиторий и `package.json.name` —
  `ord-dashboard` (lowercase с дефисом). В коде идентификаторы обычные: `OrdDashboard`, `DashboardStore`.
- **Каталоги кейсов** (`tools/`): `graph-cases.ts` — 133 проверки движка графа, `settings-cases.ts` — 91
  проверка настроек, данных, метрик и текстов, `plugin-cases.ts` — 107 проверок самого плагина на заглушке Obsidian,
  `obsidian-stub.ts` — заглушка Obsidian API и мини-DOM с управляемым временем, `vault-report.ts` — отчёт по
  настоящему хранилищу (`npm run analyze -- <хранилище> <заметка>` и `--survey=4000`), `vault-fs.ts` — чтение и
  разбор ссылок хранилища. Запуск: `npm run cases`.
  **Правило:** нашёл дефект — сначала добавь кейс, который его ловит, потом правь код; перед сборкой
  прогоняй `npm run cases` и отчёт на настоящем хранилище. Таймеры в проверках двигай через `clock`, а не
  ожиданием: время управляемое. Движение времени и обещания чередуй (помощник `advance` в
  `plugin-cases.ts`): асинхронная сборка графа не успевает выполниться, если двигать только таймеры.
- **Интерфейс** строится из одного метода `DashboardView.render()`; стили — только в `styles.css`
  на переменных Obsidian; динамика (ширина прогресса) — через `setCssProps`.
- **Совместимость.** `minAppVersion = 1.13.0` из-за декларативных настроек; язык определяется `getLanguage()`.

## Проверка перед «готово»

```powershell
npm run check    # typecheck + lint
npm run cases    # 331 проверка: движок графа, данные, тексты и настройки, сам плагин на заглушке Obsidian
npm run analyze -- "C:\Users\Ordnung\Documents\OBSIDIAN\Veritas" --survey=4000   # весь vault, нарушений быть не должно
npm run build    # main.js должен быть пересобран и закоммичен
```

Плюс то, что иначе не проверить: цвета и размеры на экране, жесты (колесо, панорама, наведение, клик),
мобильная эмуляция (`this.app.emulateMobile(true)`). Поведение проверяется в **отдельном dev-хранилище** —
никогда в основном.
